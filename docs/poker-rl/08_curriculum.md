# 08. Учебная программа

## Результат

Стабильный перенос навыков от простого покера к 5-max без обучения с нуля на самой сложной среде.

## Этапы

```text
A. Heads-up: равные стеки, мало сайзингов.
B. Heads-up: полный стартовый набор сайзингов.
C. 3-max: та же сеть, те же базовые правила.
D. 5-max: равные стеки и фиксированный action space.
E. 5-max: расширение стека и сайзингов при доказанной стабильности.
```

## Действия

1. Предобучить card/backbone/equity части на раздачах rule-based и случайных политик.
2. Запустить self-play на heads-up до превышения базлайнов и приемлемой калибровки equity.
3. После доказательного перехода A→B продолжить heads-up с полным action
   space и learning rate `×0.7`; его автоматический вариант описан в
   [16_curriculum_transition.md](16_curriculum_transition.md).
4. Перейти к 3-max и затем 5-max только после устойчивого выигрыша на
   предыдущем этапе.
5. При каждом переходе сохранять контрольный набор предыдущего режима, чтобы
   отслеживать catastrophic forgetting.

## Автоматизация переходов

Сейчас реализован только opt-in A→B. Он требует explicit reference checkpoint,
immutable evidence artifacts и не может быть включён вместе с HU promotion.
Автоматический A→B запускается только при
`require_transfer_beats_scratch=false`, потому что в нём пока нет честного
paired scratch rung. Это ограничение evidence, а не разрешение считать
transfer доказанно лучшим scratch.

Переходы C--E не автоматизируются до появления multiway expected-share head и
настоящего transfer-vs-scratch сравнения при одинаковом бюджете. Текущая
`win + 0.5 × tie` калибровка применима как scalar gate только в heads-up.

## Критерий приёмки

Каждый переход подтверждён оценкой против фиксированных ботов и предыдущих
checkpoint’ов. Утверждение, что перенос инициализации выигрывает у обучения с
нуля, требует настоящего paired scratch rung при одинаковом бюджете шагов;
одного автоматического A→B evidence для этого недостаточно.
